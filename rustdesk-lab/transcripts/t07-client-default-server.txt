Three things to notice. The default rendezvous server
is a named public one (rs-ny is one of RustDesk's
public ID servers) and registration begins by UDP to
its port 21116 — the same port your own hbbs listens
on. The service generated this client's identity key
pair on this first run ("Generated new keypair for
id"), which is what filled key_pair in t05. And when
the registration send was refused, the service did not
die: it waited and started the mediator again, which
is what it will do on any machine whose network is not
ready yet.

NAT typing — working out what kind of network the
machine sits behind, using a STUN server — is part of
starting up, because it decides how hard the machine
will be to reach (chapter 2).
