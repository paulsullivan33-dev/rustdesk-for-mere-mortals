register_pk is the client offering its own public key
to the server under its ID — the registration chapter 2
describes. Here it could go no further: the sandbox
refuses the UDP send itself (os error 1, the same wall
as t03), and hbbs was in any case already down. The
[keys_confirmed] table in RustDesk.toml stayed empty:
no server's key was ever confirmed, because no
registration ever completed. Both halves of that
sentence are this sandbox, not the software.
